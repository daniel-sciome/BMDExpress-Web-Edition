1. Architecture Overview

The data retrieval and management subsystem handles loading, enriching, and managing category analysis data. It consists of four main layers:

Backend Layer (Java/Hilla)

Server-side services that load and parse BMD analysis data.

  • CategoryResultsService (@BrowserCallable)
  • ProjectService for file management
  • DTOs generated to TypeScript via Hilla
  • BM2 file parsing and conversion
Reference Data Layer

Static pre-computed data for semantic analysis.

  • UMAP embeddings for GO terms
  • Cluster assignments (-1, 0, 1, 2, ...)
  • Semantic similarity coordinates (x, y)
  • Loaded once at app initialization
Enrichment Layer

Client-side augmentation of backend data.

  • Add clusterId to each category
  • Distinguish -1 (outlier) vs -2 (not in reference)
  • Happens during Redux reducer processing
  • Enables cluster-based filtering
State Layer (Redux)

Client-side state management and reactivity.

  • categoryResultsSlice for enriched data
  • filterSlice for filter configurations
  • renderStateSlice for CategorySets
  • Memoized selectors for derived data

Key Design Principles

  • Single enrichment point: Data is enriched exactly once when loaded into Redux
  • Type extension: CategoryAnalysisResultWithCluster extends base DTO with clusterId
  • Reference data separation: UMAP data is static, analysis data is dynamic
  • Harmonious filtering: Cluster-based filters use same pattern as other hard filters

4. UMAP Reference Data

The UMAP reference data provides pre-computed semantic embeddings for GO terms. This enables cluster-based analysis and visualization.

4.1 Data Structure

interface UmapDataPoint {
  go_id: string;           // e.g., "GO:0001234"
  x: number;               // UMAP x-coordinate
  y: number;               // UMAP y-coordinate
  cluster_id: number;      // Cluster assignment (-1 for outliers, 0+ for clusters)
  cluster_label: string;   // Human-readable cluster name
}

4.2 Data Service

Method Returns Usage
getByGoId(goId) UmapDataPoint | undefined Lookup single GO term; returns undefined if not in reference
getAllData() UmapDataPoint[] Get entire reference dataset
getClusterIds() number[] List of unique cluster IDs in reference

4.3 File Location

src/main/frontend/data/umapDataService.ts      // Service for lookups
src/main/frontend/data/referenceUmapData.ts    // Static reference data

4.4 Important Considerations

Reference Data Limitations
  • Reference data is static - pre-computed from a fixed set of GO terms
  • Analysis data may contain GO terms not in reference (clusterId = -2)
  • Cluster assignments reflect semantic similarity, not BMD analysis results
  • UMAP coordinates are used for the semantic space scatter plot

5. Data Enrichment

Data enrichment adds the clusterId field to each category at load time. This happens in the Redux reducer when loadCategoryResults.fulfilled is processed.

5.1 Extended Type

// Constants for special cluster IDs
export const CLUSTER_OUTLIER = -1;      // In UMAP reference but semantically dissimilar
export const CLUSTER_NOT_IN_REF = -2;   // Not in UMAP reference data

// Extended type with cluster information
export interface CategoryAnalysisResultWithCluster extends CategoryAnalysisResultDto {
  clusterId: number;  // -2 = not in reference, -1 = outlier, 0+ = cluster
}

5.2 Enrichment Logic

// In categoryResultsSlice.ts, loadCategoryResults.fulfilled reducer
state.data = action.payload.results.map(cat => {
  const umapData = cat.categoryId ? umapDataService.getByGoId(cat.categoryId) : undefined;

  let clusterId: number;
  if (!umapData) {
    // GO term not found in UMAP reference
    clusterId = CLUSTER_NOT_IN_REF;  // -2
  } else {
    // Found in reference - use cluster_id or mark as outlier
    const rawClusterId = umapData.cluster_id;
    clusterId = typeof rawClusterId === 'number'
      ? rawClusterId
      : (rawClusterId !== undefined ? parseInt(String(rawClusterId), 10) : CLUSTER_OUTLIER);
  }

  return { ...cat, clusterId };
});

5.3 Benefits of This Approach

  • Single lookup: UMAP data is looked up once per category at load time
  • Type safety: Extended type ensures clusterId is always present
  • Filter harmony: Cluster filtering uses same pattern as other filters
  • No repeated lookups: Selectors don't need to call umapDataService

6. Cluster Classification

Categories are classified into three groups based on their relationship to the UMAP reference data:

0+
Normal Cluster
clusterId: 0, 1, 2, ...
In reference, assigned to cluster
-1
Cluster Outlier
clusterId: -1
In reference, semantically dissimilar
-2
Not in Reference
clusterId: -2
GO term not in UMAP reference

6.1 Classification Table

clusterId Label Color Hard Filter Default Meaning
0, 1, 2, ... Cluster N Dynamic HSL Included GO term is in UMAP reference and assigned to a cluster
-1 Cluster Outliers #999999 (Gray) Excluded by default GO term is in UMAP reference but semantically dissimilar from all clusters
-2 Not in Semantic Space #fa8c16 (Orange) Included (flagged) GO term not found in UMAP reference data - anomalous, warrants investigation

6.2 Filter Behavior

excludeClusterOutliers Filter

When excludeClusterOutliers: true (default):

  • Categories with clusterId === -1 are excluded from Working Set
  • Categories with clusterId === -2 are included (but visually flagged)
  • Categories with clusterId >= 0 are included

Rationale: -1 (outliers) are known but uninteresting; -2 (not in reference) are potentially anomalous and should be visible for investigation.

8.2 selectFilteredData Implementation

export const selectFilteredData = createSelector(
  [(state: RootState) => state.categoryResults.data,
   (state: RootState) => state.categoryResults.filters,
   (state: RootState) => state.categoryResults.analysisType,
   selectEnabledFilterGroups],
  (data, filters, analysisType, filterGroups) => {
    let filtered = [...data];

    // Apply primary filter (skip for GENE analyses)
    if (analysisType !== 'GENE') {
      filtered = filtered.filter(row => {
        if (filters.percentageMin !== undefined &&
            row.percentage !== undefined &&
            row.percentage < filters.percentageMin) return false;
        // ... other primary filter checks

        // Cluster filter: exclude outliers if enabled
        if (filters.excludeClusterOutliers && row.clusterId === CLUSTER_OUTLIER) {
          return false;  // Filter out -1 (outliers)
        }
        // Note: -2 (not in reference) passes through

        return true;
      });
    }

    // Apply filter groups
    if (filterGroups.length > 0) {
      filtered = applyFilterGroups(filtered, filterGroups);
    }

    return filtered;
  }
);

10. Persistence & Caching

10.1 What Gets Persisted

Data Storage Key
Primary Filter values localStorage bmdexpress_master_filters_global
Filter Group configurations localStorage bmdexpress_filter_groups
"Remember Filters" preference localStorage bmdexpress_rememberFilters
View mode (simple/power) localStorage bmdexpress_view_mode

10.2 What is NOT Persisted

  • Category data: Re-fetched from backend on each load
  • Cluster assignments: Re-computed during enrichment
  • CategorySets: Re-created during initialization
  • Visibility state: Session-only (resets on reload)

10.3 UMAP Reference Data

Static Reference Data

The UMAP reference data is:

  • Bundled with the application (not fetched at runtime)
  • Loaded once when umapDataService is first imported
  • Indexed by GO ID for O(1) lookups
  • Never changes during application lifecycle
